What it is for

Glance already reads your audience statistics from Umami or Plausible. But some numbers are not there, because they live in your own database: the retention of your players, the number of accounts created, the installs of an app, active subscriptions…

A metrics source is a small API you add to your site. It exposes two read-only addresses: a catalogue (the list of your indicators) and series (their values, day by day). Glance connects to it with a token and knows nothing about your database: all the computation stays with you.

Each indicator becomes a “Site metric” card in the site's Dashboards tab, with its curve, its overall figure and its comparison to the selected period, like any other card.

Metric
13.2%
Day-1 retention · measured on the cohorts of Oct 12 to 17
Metric
1,842active players
Website 44% · App 55% · Others 1% (estimated)

Two sample cards: a rate with its curve, then a counter split by platform.

What you have to provide is deliberately small: two GET routes, JSON, a token. The rest of this page describes the exact contract (version 1), how Glance interprets your responses, examples, and a minimal server you can run in a minute.

Connecting the source in the app

A source is configured per site. Have the base address of your API and a token ready.

  1. Open the site in Glance, then its Dashboards tab (“Tableaux”).
  2. At the very bottom, select “Source de métriques” (the same link shows in the empty state, when there is no dashboard yet).
  3. Enter the API address: the base URL, the part that comes before catalogue and series. https:// and the trailing slash are optional, Glance adds them.
  4. Enter the token. It is kept in the device keychain, never in the settings.
  5. Select Test: Glance calls catalogue and reports “3 indicators available”, or the server's error message (see Errors).
  6. Select Save.
  7. Back in the Dashboards tab, select “New dashboard” (“Nouveau tableau”), pick the “Site metric” kind (“Métrique du site”), then an indicator from the catalogue (or a family, see Families). The card appears and follows the displayed period.

Good to know. The URL and the token travel with the end-to-end encrypted sync between your devices, but not with the transfer QR code. “Remove the source” also deletes the token and the site's “Metric” cards, which would have nothing left to show.

About the labels. The app's interface is currently in French: the screen is called “Source de métriques”, and its buttons “Tester” (Test), “Enregistrer” (Save) and “Retirer la source” (Remove the source). The steps above give both names.

The contract, version 1

Two routes, relative to the base address entered in the app. Everything is JSON, UTF-8. Field names are French and part of the contract: valeur, libelle, delai_jours…

Authentication

Every request, catalogue and series alike, carries the header Authorization: Bearer <token>. The token is a secret that you choose and that your server compares: Glance does not decode it. Serve the API over HTTPS.

Request · catalogue
GET https://api.example.com/metrics/catalogue
Authorization: Bearer <your token>
Accept: application/json

GET catalogue

GET series

Returns the values of one or more indicators over a date range.

Errors

Answer with an HTTP status code. Glance translates each one into a message it shows as-is on the card (and under the Test button). The messages are in French in the app; the English equivalent is given here.

Server responseMessage shown in Glance
404“Source non configurée sur le serveur” (source not configured on the server)
401 (missing or wrong token)“Jeton refusé” (token rejected)
400 with {"error":{"code":"…"}}“Requête refusée (code)” (request rejected); with no readable code: “Requête refusée (inconnu)”
200 with version ≠ 1“Version d'API non prise en charge” (API version not supported)
Any other status, or a body that is not a JSON object“Réponse inattendue du serveur” (unexpected server response)
No response (network, timeout: 15 s to connect, 25 s to answer)“Chargement impossible.” (unable to load)
Body of a 400 error
{ "error": { "code": "plage_trop_longue" } }

Glance does not retry automatically after one of these errors: the message stays on the card until the next refresh, so you can fix the cause.

How Glance reads your responses

The contract fits in a few fields, but each has a visible consequence. Here are the rules, as the app applies them.

Units, gaps and overall rate

  • pourcentage: valeur goes from 0 to 100 (14.3 for 14.3%). Glance divides it by 100 to display it.
  • nombre: valeur is a count. A null there counts as 0: a counter is never “not measurable”.
  • valeur: null on a percentage = not measurable (cohort not finished, or too few people). It is a gap in the curve, never a 0: “nothing measured” is not “0%”. Its headcounts do not count towards the total.
  • Privacy threshold: 5. Return null when a bucket's denominator is below 5: a rate over three people means nothing. Glance displays the valeur it receives and does not recompute it.
  • Overall rate of the card = Σ numerators ÷ Σ denominators of the measured points, never the average of the rates. It is not displayed if Σ denominators is below 5.
  • Buckets you do not send are filled in: a gap for a percentage, 0 for a count. Points outside the displayed window are dropped.

Delays and cohorts (delai_jours)

The day-7 retention of day D is only known on day D + 7. To keep the card aligned with the selected period, Glance places each point at its measurement date, not its cohort date.

  • Your t is the cohort day; valeur is its rate, measured once delai_jours have elapsed.
  • For a period from October 15 to 21, a D7 indicator receives de=2026-10-08&a=2026-10-14: the cohorts of the 8th to 14th, displayed at the dates of the 15th to 21st.
  • A point whose measurement day is not over (today) stays a gap, whatever the server answers. On “Today”, a D1 therefore has nothing measurable, and the card says “Pas encore mesurable sur cette période” (not yet measurable on this period).
  • In months, Glance asks for months and shifts each bucket by delai_jours before attaching it to its month. Aggregate the whole month on the server: every single day often falls under the threshold of 5.

Families (famille)

Several indicators that differ only by their delay (D1, D7, D30) form a family. In the editor, the user picks the family once; Glance picks the member at each computation: the largest delay that fits four times in the displayed window, otherwise the shortest.

PeriodLengthMember chosen
Today, 24 h, 7 days1 to 7 daysD1 (D7 would need 28 days)
30 days30 daysD7 (28 ≤ 30; D30 would need 120)
12 months365 daysD30 (120 ≤ 365)

A single card thus follows the period, instead of three cards of which two are empty. It shows the family name and “J7 · s'ajuste à la période” (adjusts to the period). A sample catalogue is further down, in Examples.

The members of a family must share the same unite (Glance uses the one of the shortest delay), and libelle_famille is enough on just one of them.

Late data (donnees_jusqu_au)

Some sources publish with a delay (an app store's reports, for example). Announce the last published day, YYYY-MM-DD:

  • The buckets after it are gaps, even for a nombre: a day not yet published is not a day at 0. They are left out of the totals.
  • The card notes “Données jusqu'au 18 oct.” (data up to Oct 18). If the whole window comes after, it says “Pas encore publiées” (not yet published).
  • The date applies to the series' t. With a delay, Glance shifts it by delai_jours, like the points.
  • On the server, it is advisable to return, for the month bucket that contains this date, its partial sum, and null only for a bucket that starts after it.

Segments (segments and totaux)

A nombre can be split into parts (website, app, other platform…). Declare them in the catalogue, then give each part's value in every point.

  • The card draws a “Total” curve plus one curve per part (clickable legend), then one bar per part over the period.
  • A point without a segments key is unknown, not zero: the source could not split that day yet. Each part is a gap there; valeur remains the true distinct total.
  • totaux gives the number of distinct people over the whole range for each part. The bars are computed from it, never from the sum of the points: a player active on two days would count twice.
  • The sum of the parts may exceed the total, if one person goes through two platforms: the bar is therefore read as a share of Σ totaux.
  • As long as no part has a value, the card stays a plain counter. Segments do not apply to a pourcentage.

Hours (granularites)

By default, even on “Today”, Glance asks for days and the card shows one point per day. It asks for granularite=heure only if all three conditions are met:

  • the displayed period reads in hours (“Today”, “24 h”…);
  • the indicator announces "heure" in granularites;
  • it has no delay (delai_jours missing or 0).

Then: de and a remain days (the source returns whole days, Glance keeps only the hours of the window); t is YYYY-MM-DDTHH:00 in local time, one point per hour, empty ones included (23 or 25 points on daylight-saving days); 30 days at most, beyond that answer 400 plage_trop_longue. The totaux cover the whole days.

Limits and good practice

  • 400 days at most per request. For “All time” or a longer custom period, Glance itself brings de back to a − 399 days: the earlier buckets stay empty (a gap for a %, 0 for a count).
  • Version: any version other than 1 is rejected. An incompatible change to the contract will come as a new version, not a silent change.
  • Cache: cache responses on the server, 5 minutes is fine. Several cards and several devices query the same source.
  • Read-only, no personal data: expose aggregates only. The threshold of 5 exists so that no figure points at a person.
  • Token: compare it in constant time, revoke it if a device is lost, and never put it in a URL.

A minimal example server

About sixty lines of Node.js, no dependency: the native http module is enough. It serves a catalogue of two indicators (comptes_crees, a count, and retention_j1, a percentage with a delay), checks the token, validates the parameters, handles days and months, applies the threshold of 5 and the wait for the cohort. The figures are made up: replace dayStats with your queries.

server.js · node server.js
const http = require('node:http');

const TOKEN = process.env.METRICS_TOKEN || 'change-me';
const DAY = 86_400_000;
const MAX_DAYS = 400;
const MIN_DEN = 5; // privacy threshold: below it, valeur = null

const CATALOGUE = { version: 1, indicateurs: [
  { id: 'comptes_crees', libelle: 'Accounts created', description: 'Sign-ups of the day.',
    unite: 'nombre', granularites: ['jour', 'mois'] },
  { id: 'retention_j1', libelle: 'Day-1 retention', description: 'New users back the next day.',
    unite: 'pourcentage', granularites: ['jour', 'mois'], delai_jours: 1 },
] };
const DELAI = { comptes_crees: 0, retention_j1: 1 };

// Replace with your queries: one day -> { n, d } (numerator, denominator).
const dayStats = (id, day) => {
  const k = Date.parse(day) / DAY;
  return id === 'comptes_crees' ? { n: 20 + (k % 7) * 3, d: 0 } : { n: 10 + (k % 5), d: 90 + (k % 9) };
};

function series(q) {
  const ids = (q.get('ids') || '').split(',').filter(Boolean);
  const de = Date.parse(q.get('de')), a = Date.parse(q.get('a'));
  const gran = q.get('granularite') || 'jour';
  if (!ids.length || ids.some((id) => !(id in DELAI))) return [400, 'indicateur_inconnu'];
  if (isNaN(de) || isNaN(a) || a < de) return [400, 'dates_invalides'];
  if ((a - de) / DAY + 1 > MAX_DAYS) return [400, 'plage_trop_longue'];
  if (gran !== 'jour' && gran !== 'mois') return [400, 'granularite_inconnue'];
  const today = Date.now() - (Date.now() % DAY);
  return [200, { version: 1, series: ids.map((id) => {
    const buckets = new Map();
    for (let t = de; t <= a; t += DAY) {
      const day = new Date(t).toISOString().slice(0, 10);
      const key = gran === 'mois' ? day.slice(0, 8) + '01' : day;
      const b = buckets.get(key) || { n: 0, d: 0, done: true };
      const s = dayStats(id, day);
      buckets.set(key, { n: b.n + s.n, d: b.d + s.d, done: b.done && t + DELAI[id] * DAY < today });
    }
    return { id, points: [...buckets].map(([t, b]) => ({
      t,
      valeur: id === 'comptes_crees' ? b.n
        : b.done && b.d >= MIN_DEN ? Math.round((1000 * b.n) / b.d) / 10 : null,
      numerateur: b.n, denominateur: b.d,
    })) };
  }) }];
}

http.createServer((req, res) => {
  const url = new URL(req.url, 'http://x');
  const send = (status, body) => {
    res.writeHead(status, { 'content-type': 'application/json' });
    res.end(JSON.stringify(status === 400 ? { error: { code: body } } : body));
  };
  if (req.headers.authorization !== `Bearer ${TOKEN}`) return send(401, {});
  if (url.pathname === '/metrics/catalogue') return send(200, CATALOGUE);
  if (url.pathname === '/metrics/series') return send(...series(url.searchParams));
  send(404, {});
}).listen(3000, () => console.log('http://localhost:3000/metrics/'));

Start it with METRICS_TOKEN=my-token node server.js, and try it with curl:

Terminal
curl -H 'Authorization: Bearer my-token' \
  http://localhost:3000/metrics/catalogue

curl -H 'Authorization: Bearer my-token' \
  'http://localhost:3000/metrics/series?ids=retention_j1&de=2026-10-12&a=2026-10-18&granularite=jour'

Then, in Glance, enter the address http://<your-machine-ip>:3000/metrics/ and the token. In production, put it behind HTTPS (a reverse proxy is enough): the token travels in every request.

This is only a skeleton. It handles neither heure, nor delai_jours beyond the cohort wait, nor segments, nor caching. Add what your indicators need by following the previous sections.
